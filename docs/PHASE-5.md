# Phase 5 — stabilization and release qualification

This phase is in progress. The October 18 iteration adds hands-free presence, the owner's corrected Progre artwork and a session-owned control panel. It does not declare the remaining physical lifecycle/release gates complete.

## Delivered in this iteration

- The default is an installed vision-and-tool-capable model. Prefer the image-qualified `qwen3.5:4b` when it fits available memory; otherwise choose another fitting nonexperimental model advertising both capabilities. No reasoning model is downloaded. Explicit text-only selection and existing conversation history remain available. This workstation was switched to a new vision conversation while retaining its older coding conversation.
- Addressed spoken commands include exactly one fresh private camera frame whenever the camera is enabled. The same selected LampOS/OpenCode/Ollama model answers text and image questions. Missing, stale or unsupported images fail before sending a text-only guess. Images included in a conversation may remain in the isolated agent's local history; the replaceable live frame is deleted on sleep.
- Wake up starts the selected camera, local CPU Whisper/Silero microphone listener and local Piper response path together. The default phrase is `hey progre`, pronounced **PRO-Greh**. Pinned LampOS sentence-position/bare-wake matching gates the transcript; no cloud realtime conversational model starts. A bare phrase gets an acknowledgement; commands may follow without another phrase for ten seconds after processing/playback. The listener discards audio while the selected model or speaker is busy. Ambient transcripts are never saved as chat.
- Go to sleep, Stop all, lock, session/model switch and controller shutdown stop owned capture, listener and playback process groups. Unlock does not wake anything. Changing devices leaves presence asleep. A missing saved device is never silently replaced.
- A native lower-left Wake up / Go to sleep button is visible on exposed desktop space and hides behind ordinary windows, during overview and while locked. It invokes one fixed authenticated local toggle helper through an on-demand user unit; the compositor receives no credentials or raw media.
- The panel uses its own private Chrome application profile and systemd control group, bound to `graphical-session.target`. Avalon no longer opens the shared Firefox profile. Logout stops the owned panel and controller, and controller shutdown releases media/runtime. Existing unrelated Firefox sessions are preserved.
- Progre is the latest supplied **face-only** character, with tiny hands and feet directly attached, no torso/chest/neck. Side spheres are eyes; white slashes are the nose; central enclosed zigzag is the mouth. A transparent reference-derived texture replaces the invented green/procedural robot, with bounded GPU light, gaze and speech deformation. The other three avatars retain their procedural volume renderers. The background star field is removed; flowing rays remain.

## Evidence and limits

`evidence/phase-5/presence.json` distinguishes actual hardware, synthetic PipeWire routing and unit checks. The real Logitech Brio 101 camera produced a fresh image that the actual selected `qwen3.5:4b` answered through LampOS. Its generated reply was played through the Ubuntu default HDMI speaker route; process playback was observed, not human audibility rated. Sleep removed the frame and released the devices. A generated PRO-Greh utterance crossed a virtual PipeWire sink/source, local VAD/Whisper and the native wake classifier. This is not a claim that the owner's live wake phrase has been calibrated. Direct onboard capture was saturated/noisy; the workstation now follows Ubuntu's selected Brio microphone and selected HDMI speaker, rather than retaining the noisy analog input. All devices remain asleep at handoff.

OpenCV 5 lacked the existing Haar detector interface in this installation; the isolated media dependency is now pinned to 4.13.0.92 and actual camera capture was requalified. PipeWire returns exit 1 at its requested sample limit on this machine; a complete bounded recording is retained rather than discarded. Local speech segmentation uses the installed CPU Silero VAD with preroll and a 2.5-second speech-end interval, rather than mistaking loud background input for continuous speech.

The new GNOME source and artwork are qualified in a disposable real GNOME compositor and installed for the login session. GNOME caches imported extension JavaScript; **one normal logout/login is required** for version 5's native textured portrait and corner button. No forced logout, Shell replacement or broad browser termination was performed. The control panel can show the new artwork immediately after refresh.

Still open: the owner's live spoken interaction, actual device unplug/replug/default-route changes, lock/logout during physical capture, long-session resource/recovery tests, update/uninstall and diagnostics delivery. The earlier fixed-30-FPS humanoid CPU gate remains recorded in phase 3; this change does not retroactively pass it.
